# 玩家从者抱起与御主保护

本次仅适用于互相缔结有效契约的玩家御主和玩家从者，不给 NPC 增加抱起能力。

## 保护条件

- 御主作为真实乘客被自己的从者抱起时，伤害全额转给从者。受伤、破防和眩晕不解除抱起；从者的防御和闪避仍受其原有资源、冷却与行动条件约束。
- 御主和从者距离不超过 2 格，且从者主动防御有效时，同样全额转移伤害。这一条件不要求抱起筋力。普通靠近、被动减伤、眩晕或破防后的无效防御不触发近身保护。
- 有效契约校验包括双方存活、同维度、互相对应的 UUID、同一个非空契约 ID，以及从者仍处于变身状态。保护不依赖保存的抱起标签。

## 操作

- 双方均可 Shift＋右键对方请求抱起；筋力系数必须严格大于 E 的基础系数，缺失参数拒绝抱起。双方都不能正在骑乘，从者不能已有乘客，服务端检查正常交互距离和双向视线。
- 同一次交互被消费，避免副手与实体精确交互重复执行。已抱起时普通右键不切换状态。
- 御主重新按 Shift 下来；用于请求抱起的 Shift 必须先松开。从者 Shift＋右键放下。任一方 TAB 优先放下，并消费本次 TAB，直到松开后恢复其他功能。
- 从者可移动、疾跑、跳跃、防御、闪避；普通攻击、主动技能、宝具和召唤物指挥受服务端限制。御主保留观察、施法、令咒和道具操作，禁止普通攻击和自行移动。
- 抱起前中断蓄力、吟唱和持续操作。已释放弹丸、独立召唤物与独立限时效果继续运行。
- 地面放下搜索附近无碰撞位置；空中允许放下，之后正常承受摔落伤害，无额外无敌时间。

## 伤害结算

`原始命中 → 确定承伤者／归并同段范围命中 → 从者的伤害修正与防御 → 实际扣血`

`ServantMasterDamageRouter` 在 `ServerPlayer.hurt` 的入口完成路由，御主不进入其护甲、护盾和减伤事件。转移保留原始 `DamageSource` 对象及其技能包装；递归交付用临时上下文标记，避免再次转移或重复修正。共享伤害入口也会保留预先计算伤害的上下文。

火焰、爆炸、毒、凋零和特殊必杀均可转移。抱起期间御主的摔落和墙内窒息伤害被免除。已有负面状态不被清除，生命换魔力等直接生命支付仍由御主支付。

因果斩断等目标标记作用于最终承伤者。涉及 `hurt()` 之后强制扣血、强制死亡的旧结算，使用 `special()` 包住整个结算，防止后续逻辑重新伤害御主。其他护盾、代伤和特殊防御继续按原规则处理。

从者死亡时不溢出伤害。同一攻击段内保存的保护对象不随死亡清理而改变；后续攻击重新检查保护条件。原有从者死亡导致御主生命上限下降 20% 的契约反噬继续生效，它与本攻击的伤害转移分别结算。

## 范围攻击内部接口

```java
try (var segment = ServantMasterDamageRouter.attackSegment()) {
    for (LivingEntity target : targets) {
        target.hurt(source, damageFor(target));
    }
}
```

一个作用域对应一次攻击的一个伤害段。两人的候选伤害取最大值，之后只执行一次防御、消耗资源和扣血。不同作用域独立结算，不能用技能来源 ID、整次宝具施放 ID 或服务器 tick 作为归并键。

多弹丸每发分别建立作用域；多段和持续伤害每段／每跳分别建立作用域。原版爆炸由 `ExplosionCarryDamageMixin` 提供作用域；MOD 范围技能、投射物爆炸、光束、冲击波、斩击及公共范围辅助入口显式建立作用域。

在范围作用域内通过 `queueServerWork` 按目标安排延迟回调时，调度器保留该作用域的身份，并分别处理不同延迟的伤害跳数；同一 tick 的其他攻击不会加入这个作用域。

## 生命周期与显示

死亡、离线、解除变身、契约清除／解除、跨维度、数据重载和服务器停止时清理乘客关系与临时状态。抱起状态使用单独的客户端消息同步，附近观察者无需读取双方私有变量；后加入追踪的观察者也会收到状态。

保留原抱姿，防御动作可覆盖从者手臂，御主施法和令咒动作不再被抱姿强制覆盖。双方 HUD 显示抱起及放下提示，从者技能栏显示禁用。
